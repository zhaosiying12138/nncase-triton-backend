# CUDA Triton fused-kernel modes

`--fused-kernel={off,compute,compute-ccl}` is carried as a CUDA/NTT target option and emitted into the generated Triton module metadata as `fused_kernel`.

The persistent tile contract belongs to the CUDA/Triton baseline, not to a separate fused-kernel mode. Baseline admission defaults to `PE=16`, can be overridden by `NNCASE_CUDA_TILE_PE`, rejects mismatched PE counts, and rejects devices whose SM count cannot resident the requested PE count. Persistent kernels must use a single-dimensional `grid=(PE,)` and `pe = tl.program_id(0)`.

Modes:

- `off`: default. Uses the persistent tile baseline but disables whole-function compute fusion, so it remains the regression baseline for launch-sequence fusion.
- `compute`: enables CUDA pass-level fusion for PE-local compute chains that are already backed by Triton-native helpers. The pass runs after `AutoDistributed` has searched the shard strategy and before CUDA affine selection/AutoTiling/TIR lowering, so it does not force a fixed sharding choice. The pass layer emits explicit `Fusion("cuda.*", "cuda", ...)` markers for dense flash attention, swish/mul MLP chains, full gate/up/down MLP chains, `LayerNorm`/RMSNorm adjacent transpose/matmul patterns, RoPE, and RoPE angle `mul -> cos/sin` chains. Codegen lowers those explicit Fusion names to native helpers such as `_nncase_pe_flash_attention_rank4_kernel`, `_nncase_pe_swish_mul_rank4_kernel`, `_nncase_pe_matmul_silu_matmul_mul_matmul_kernel`, `_nncase_pe_layer_norm_matmul_kernel`, `_nncase_pe_mul_unary_rank4_kernel`, and `_nncase_pe_rope_rank4_kernel`. Patterns that need sequence/head-dim cross-PE CCL are rejected in this mode. Older generated-Python whole-function matchers remain only as a transition path for compatibility cases that have not yet moved to pass-level Fusion rules. Whole-function matches that contain CCL launches are rejected in this mode.
- `compute-ccl`: CCL-only tail mode. It does not register the CUDA compute-fusion pass and generated metadata must not contain `fusion.cuda.*` compute launches from this mode. Instead, codegen plans opportunistic `gather_reduce_scatter` tails from data dependencies: if a GRS input buffer has a unique producer, the producer metadata carries `ccl_tail.<producer>.grs`, the original GRS launch is marked `elided_by_ccl_tail=true`, and unsupported/non-unique sites remain explicit with a diagnostic attribute. If the producer is a function launch, the planner drills into the callee and attaches the tail to the unique nested writer of the parent buffer. `tensor_load`, `tensor_store`, `paged_attention`, and KV side-effect launches remain explicit.

Python test runners can set `NNCASE_CUDA_FUSED_KERNEL` to override the compiled metadata. The Qwen3 profiling helper also accepts `--fused-kernel`; use `--fused-kernel compute` for compute-only pass-fusion regression and `--fused-kernel compute-ccl` when validating CCL-tail planning. The helper always sets `NNCASE_CUDA_TILE_PE` from `--cuda-pe` for the persistent tile baseline.

Current CUDA/Triton strict mode still rejects unsupported native lowering instead of falling back to torch/CPU. For first-pass Qwen3 validation, use small token counts and `PE=16`.

Current implementation note: the mode/API plumbing, baseline admission check, and generated multi-PE native Triton launches use the persistent `grid=(PE,)` helper. Explicit native CCL materialization still writes directly to the API-selected destination GMEM buffers. Planned CCL-tail sites reserve scratch counter bytes in `ccl_scratch_bytes`, use the existing `ccl_scratch_pool` ABI for the tail barrier state, and are recorded in metadata/launch summaries as producer-side `ccl_tail.*.grs` sites plus an elided original GRS ordinal.

Attention note: dense flash attention and paged attention are not conflicting paths. Dense attention graphs are fused through the pass-level `cuda.flash_attention_*` Fusion rule. The Qwen3 autoregressive graph uses paged KV-cache layout, so its `paged_attention` op lowers to `_nncase_paged_flash_attention_rank3_kernel`, a prewritten Flash-style online-softmax Triton kernel that reads the current Head/Dim/Seq paged KV cache through owner/slot tables. The legacy paged-attention kernel remains in the generated source as bring-up/reference code, but the native paged-attention dispatcher launches the paged-flash kernel and tags launch metadata with `"paged_flash": True`.

The old partial-add compute+CCL shortcut is intentionally disabled for this mode. Partial-input adds materialize the partial value with the existing CCL helper and then run the PE-local add, matching `off` semantics.
